## Known limitations

- Revision 2 approval is not acceptance of the implemented interface. UI-2 is automated-green and physically pending.
- **The current UI is not the final appearance.** The user reported on 2026-10-11 that it is closer to the approved mockup than at the start but still not in line with it. Visual acceptance needs a screenshot-versus-mockup gap list, closed or explicitly accepted with the user.
- **Default editor performance:** the measured fix at `8b78ecf` is automated only. Physical COSMIC typing, undo, and scrolling in `README31.SAM` with the default build remain pending.
- **UI-2 deviations:**
  - The pinned libcosmic tab bar has no per-tab tooltip (full path/source type) and no accessibility node.
  - The status-bar page number is not caret-derived.
- SAM import is intentionally lossy: character controls beyond paired bold/italic, frames, tables, fields, graphics, headers/footers, and exact layout are reported but not modeled yet. Their format is specified (`docs/research/SAM_PAGE_FRAME_SPEC.md`) and the model is decided; import is Phase 2.4, after the 2.3 model work.
- The unified editor's public libcosmic/Iced highlighter supports per-range font and color, but not variable font metrics, paragraph spacing, or underline. Those attributes remain preserved but are not all visible during editing; full WYSIWYG acceptance therefore remains open. Exact legacy font-name matching is not implemented.
- Collapsed-caret typing attributes and selection across shaped pages/frames are pending.
- Associated style fidelity cannot be validated for the 143 corpus documents referencing absent `SMARTEXT.STY` or `PRO21.STY` files.
- SAM write-back (since 2026-11-04, the user's decision; Save As only before, Phase 4 decision A): Save writes over a document's `.SAM` after the loss check, keeping the original as `NAME.SAM.bak` the first time; Save As onto an existing `.SAM` asks first. Frames in table cells (flag 0x20) are Where placed frames in the model, so an edit that moves their table leaves them behind; Ami Pro moves them with the table.
- Pagination is shaped layout (Phase 2.5) compared with Ami Pro's caches. Since 2026-10-12 styles and paragraphs carry indents, spacing, break rules, and alignment, single-spaced line heights are calibrated from each document's caches, and character overrides (`<:f…>`, the `<+X>` attributes, the styles' colour and attributes) are imported, laid out, and drawn. User's corpus: 686 of 1,097 page ends, 298 of 394 page counts (`docs/research/LAYOUT_COMPARISON.md`). Fonts never cached alone (`<:f…>` faces, bold runs) take their own metrics, and an empty paragraph holding only a font change takes its style's line height.
- The pinned Iced `text_editor` highlighter cannot express per-span size, underline, or paragraph spacing and cannot consume the derived rich buffer. `docs/Design/RICH_EDITOR_ARCHITECTURE.md` records the incremental custom-surface boundary; the tested Iced editor remains active until a replacement clears interaction regressions.
- The feature-gated rich surface's corrected multiparagraph mouse selection, improved scrolling, mouse-wheel scrolling, responsive empty-document typing, and primary large-import typing responsiveness have passed physically. Untested regression checks and broader paragraph-spacing/navigation/Enter/join acceptance, accessibility semantics, and visual preedit placement remain before production activation.
- A dedicated nested/headless Wayland run is not currently proportionate: `cosmic-comp` is available, but no supported input-injection harness is installed, and compositor launch alone would not test pointer mapping. The shaped-widget integration test covers deterministic geometry; physical COSMIC remains mandatory.
- The corrected one-paragraph focus/input and caret behavior passed focused physical COSMIC testing. That evidence does not automatically accept the newly expanded multiparagraph path.
- BetterOffice remains an experiment only. Its source positions are UTF-16 rather than the model's UTF-8 byte offsets, its complete header/footer path uses an additional region/extras contract, and using its shaped display list would require a new libcosmic renderer bridge. Pagination accuracy against Ami Pro was not measurable because no currently modeled fixture has authoritative line/page geometry.
