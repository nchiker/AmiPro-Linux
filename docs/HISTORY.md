## How SAM/STY parsing works (`crates/ami-formats/src/lib.rs`)

1. **`parse(bytes, kind)`**
   - Enforces limits: 64 MiB per file, 2M lines, 1 MiB per line.
   - Refuses Lotus Word Pro files (they start with `WordPro`; some are named `.SAM`) with a message that says so.
   - Truncates at the first NUL byte, which marks embedded OLE or bitmap payloads. After `[edoc]`, a line that starts with `[` but is not a section header also ends the sections, with a warning (a payload without NUL bytes; one user style sheet).
   - Decodes as UTF-8, falling back to Windows-1252.
   - A line that is `[name]` after trimming starts a section. Nested `[fnt]` under `[tag]` ends up as a flat sibling section. Other non-empty lines become values of the current section, with leading tabs and spaces trimmed.
   - Stops at `[Embedded]`.
   - Unknown section names are reported but kept in `LegacyFile.sections`. `safe_to_overwrite_original` is always `false`.
2. **Styles (`collect_style_specs`).**
   - In each `[tag]`, `values[0]` is the style name.
   - The first following `[fnt]` gives: `values[0]` family (default Times New Roman), `values[1]` size in **twentieths of a point** (200 means 10 pt; default 12), `values[2]` the colour (`COLORREF`), and `values[3]` flags (1 bold, 2 italic, 4 underline, 8 word underline, 16 upper case, 32 small caps, 64 double underline, 128 strikethrough, 256 superscript, 512 subscript, 1024 lower case, 2048 initial caps, 4096 protected text; the face's kind bits become the document's face kinds).
   - External STY specs load first. Specs embedded in the SAM then override them by lowercased name.
   - Since Phase 3 (2026-10-12) styles also carry indents (`[algn]` and the `[nfmt]` trailing right indent), alignment (`[algn]` flags), spacing (`[spc]`), and break rules (`[brk]`); since 3.2 also `[line]` rules, `[spec]` bullets and numbers, Next style, the style's own tabs, hanging indent, and Text Tightness. **A line of only tabs and spaces is an empty value** (an empty `[spec]` text or `[nfmt]` currency); `<*>>` (code 0x1E) decodes. A SAM's own `[tag]`s are its document styles, the STY's are sheet styles, names defined nowhere are missing (VM fixture ST1). Paragraphs carry their own `<:I…>`, `<:S…>`, and `<+@ABC>` overrides (`ParagraphFormat`); alignment marks OR together (left+right is centre; justify with another mark is the style's), per the decompile.
   - `StyleId`s are assigned in alphabetical order of name.
3. **Body (`edoc_paragraphs`).** Verified against Ami Pro 3.1 on 2026-10-11; the full rules are in `docs/research/SAM_FORMAT_NOTES.md`.
   - Decodes from `[edoc]`, always as CP-1252.
   - A blank line separates paragraphs. Wrapped physical lines are concatenated with no added separator, because Ami Pro keeps the trailing space.
   - The body ends at a lone `>` line (or `[Embedded]`) **outside any control**. Notes (`<:N…`) and `<:h…` span lines and contain their own blank and `>` lines; before the 2026-10-11 fix this truncated 27 of 160 corpus documents.
4. **Paragraph (`parse_sam_paragraph`).**
   - An optional `@Style Name@` prefix sets the style. **An untagged paragraph is Body Text** (resolved by name; Ami Pro writes Body Text untagged wherever it sits in the style sheet). A tag does not carry over to the next paragraph.
   - Escapes: `<<` is `<`, `<;>` is `>`, `<[>` is `[`, `</X>` is CP-1252 byte X+0x40, `<\X>` is byte X+0x80. `@@` is `@` only at the paragraph's first text position.
   - The scanner walks `<…>` controls, counting nesting depth (`<<` does not nest). The `<+X>`/`<-X>` attribute marks for `!"#$)%&'+,-(` become `CharacterRun`s (byte ranges): off returns bold, italic, the underlines, and the caps to the style (`None`), while strikethrough and the scripts end (`Some(false)`); each caps mark replaces the others. `<:fSIZE,KFACE,R,G,B>` sets the run's face, size, and colour, each replacing the last, with empty fields and `<:f>` the style's (decompiled reader rules in `SAM_FORMAT_NOTES.md`). In a paragraph without text these changes become its `end_format`. Since 3.3 `<+*>` (protected text), `<+.>` (no hyphenation), and `<:O±C>` (overstrike) are runs too. A bare `@Style@` line, and a blank line where a paragraph starts, are empty paragraphs (decompiled reader).
   - Tabs are literal tab characters. `<:t n>` is a **table anchor**, not a tab (VM fixture TB1; fixed 2026-10-11). Since 2.4, anchors, breaks, floating headers and footers, and page-number fields become U+FFFC inline objects, `<**>` and `<*7>` become U+2028 and U+00AD, and other controls are kept as zero-width legacy marks and listed in `unsupported_controls`; `<:#…>` caches are dropped.
   - An unbalanced `<` causes the rest of the paragraph to be emitted raw. The corpus audit reports control-like text left in imported paragraphs (0 leaks at the fix).
5. **Style resolution.**
   - An unknown style name creates a fallback style cloned from Body Text (or the first style).
   - `import_sam_path` looks for the `[sty]` file case-insensitively in the SAM's directory and in a `styles` directory there, one level up, or two levels up (the directory name in any case, as copied DOS trees keep `STYLES`; the user's corpus files documents in client folders beside it); a sheet that is not found is marked (`STYLE_SHEET_MISSING_KEY`) so that the loss check reads written copies back without one; `import_sam_path_with_style_directories` also searches given directories (Ami Pro's style-sheet path; `AMIPRO_STYLES` for the audit and the comparison), and the report records the path found.
   - A file whose first section is `[encrypt]` is password-protected and refused as such.
   - 143 of the 160 corpus SAMs reference `SMARTEXT.STY` or `PRO21.STY`, and neither is on the ISO.
6. **The writer (Phase 4).** `sam_document` writes what the importer read, from the model and the kept legacy data (unknown sections, frame fields, controls); the importer keeps a value only where the writer would write another one (`drop_derived_values`, 4.5's rule). Save As writes `.SAM` (onto an existing one after asking); since 2026-11-04 Save on a SAM writes over it after the loss check, keeping `NAME.SAM.bak` the first time.

The native format is line-oriented and tab-separated: an `AMIPRO-LINUX/2` header, then `title`, `page`, `style`, `paragraph`, and `run` records, with `\\`, `\n`, and `\t` escapes. The decoder is strict and rejects unknown records.

## Ami Pro's document model (from the 3.1 user's guide, chapters 8, 14–16)

Ami Pro is a **page- and frame-based, desktop-publishing-style** word processor, not a Word clone. Frames are integral from the start.

- **Page layout.** Each style sheet carries a standard page layout: margins, columns and gutter, tabs, lines, header/footer format, and page settings.
  - Each page has exactly one layout. *Inserted page layouts* change it mid-document. Mirror and left/right pages are supported.
- **Frames.** A frame is "a mini-document within the main document."
  - Each frame has its own layout: columns, tabs, margins, lines/shadow, fill, and rounded corners.
  - A frame holds text or a picture. **Text frames are full mini-documents:** their own styled paragraphs (new frame text starts as Body Text), up to 22 tabs, columns with gutter, column balance, and a line between columns. Frames are created and moved in Layout mode.
  - Frames can also sit in headers, footers, and table cells.
  - Linked text flow between frames is not described in the 3.1 guide; treat it as unverified.
  - Frames can be transparent or opaque, layered, grouped, and can overlap.
  - Pictures **must** be in frames. Drawings, charts, equations, and images live in frames.
  - Tables live in the main text or in frames.
- **Placement (anchoring).**
  - *Where placed*: fixed position on the page.
  - *With para above*: anchored to a paragraph.
  - *Flow with text*: anchored to a character.
  - *Repeat all pages* and *Repeat right/left*: the frame becomes part of the page layout.
- **Text wrap.** *Wrap around*, *No wrap around* (text flows behind/through), and *No wrap beside*.
- **Format decoded and, since Phase 2.4, imported.** `[lay]`/`[rght]`/`[lft]` page layouts, `[hrght]`/`[frght]`/`[hlft]`/`[flft]` header and footer layout frames, `[frm]`/`[lyfrm]`/`[frmlay]` frames, `[repfrm]`, `[tbl]` table frames, `[isd]` picture frames with `[Embedded]` objects, `[pg]` (a page cache), and the main-text marks `<:A n>` (frame anchor), `<:t n>` (table anchor), `<:p…>` (page break / inserted layout), `<:c>` (column break), `<:H…>`/`<:h…>` (floating header/footer) are specified in `docs/research/SAM_PAGE_FRAME_SPEC.md` and imported (mapping table in `docs/research/FORMAT_COMPATIBILITY.md`, "Phase 2.4 mapping"). `master` and footnotes are not yet examined.
- **Phase 2.2 checks (V10–V23, X06):**
  - A fixed frame keeps its page, and Ami Pro adds pages so it exists.
  - Anchored frames move with their paragraph or line at a page end.
  - Page frames paint above repeating frames, and header text wraps around frames. Where placed frames paint above anchored ones, whatever their order (FC7G, FC8); files list them first (`11c8:3ba0`).
  - Groups move and delete as one unit.
  - `<:h` is the floating footer, and the byte after `<:H`/`<:h` is a flag set.
  - `<*X>` is byte X−0x20: `<**>` is a hard return and `<*7>` a discretionary hyphen.
  - `<:t n>` and `<:A n>` share one numbering.
  - A frame holds exactly one of text, a table, or a picture.
- **Model decided (2026-10-11) and implemented in Phase 2.3 (2026-10-11/12).** The design:
  - typed IDs, including `ParagraphId`;
  - `TextPosition { flow, paragraph, byte }`;
  - U+FFFC inline objects (anchors, breaks, floating headers/footers) plus zero-width legacy marks;
  - a flows map, ordered `PageLayout`s, and frames with one `LayoutBox` type and one `frame_stack` (since the ruler run a box keeps uneven columns' edges, `LayoutBox::column_edges`, from its text area's left);
  - pages as layout output;
  - undo as `Arc`-shared document roots behind typed commands, replacing both current mechanisms;
  - native v3 as single-file text with base64 blobs.
