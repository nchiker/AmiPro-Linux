## Choices made in the run (TQ…, also in `DECISIONS.md`)

- **TQ1** A TOC mark of a level that no style has (Ami Pro's TOC Options left it empty): with TOC levels in the document its page is right aligned without a leader (TI1T2's level 3), without any its page follows its text with no separator (TI3T: "FirstPage 1").
- **TQ2** A generated TOC's page cells hold the page as shown (`1`). Ami Pro writes a numeric cell with two decimals (`1.00`) and reads either as the number. Ami Pro shows numeric cells through the style's Numeric format (`[nfmt]`; General drops `.00`), which the app does not do yet: imported numeric cells show their stored text (`5.00`; about 550 two-decimal cells in the user's corpus). Left for the table-data run (formulas), which owns numbers in cells.
- **TQ4** A record goes into the text inline, as Ami Pro's glossary does: its first paragraph joins the text before the caret and its last the text after (Insert › File… inserts whole paragraphs). Ami Pro's Undo after a record was erratic (GLO0); the app's is one step.
- **TQ5** Generating a TOC in the document also stores the levels it used as `[toc]` (one undo step with the TOC), as TOC Options' OK stores them in Ami Pro, so that Ami Pro's TOC, Index makes the same TOC again (twin ATI1: without `[toc]` Ami Pro kept only the marked entry). The app takes TOC Options' first state (the outline levels) even before the levels are opened; Ami Pro without `[toc]` uses marks only (TI3T).
- **TQ6** An index (or TOC) in a new document takes `_INDEX.STY`'s (`_TOC.STY`'s) styles and page settings, not the sheet's layout frames: Ami Pro's index file shows the sheet's "Index" title frame, the app's does not. This is Use Another Style Sheet's open gap (the sheet's header and footer frames), left for it.
- **TQ3** Generating an index does not rewrite the marks' value words with their pages, which Ami Pro's generation does before it saves the source. They are a cache that nothing reads, and changing the source would make it modified and add an undo step.
